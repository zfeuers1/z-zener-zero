# ZF0001 - Wearable Voice Logger

## Overview
Compact wearable device for recording voice notes with live WiFi streaming to a server. Features GPS coordinate tagging, rechargeable battery operation, and optional SD card backup.

## Key Features
- **ESP32-S3** WiFi microcontroller with 8MB flash + 8MB PSRAM
- **Analog microphone** input via 3.5mm TRRS audio jack
- **GPS tagging** via u-blox MAX-M10S GNSS module
- **Battery powered** with Li-ion charging from USB-C
- **3-5 hour runtime** with 1000-2000mAh battery
- **MicroSD backup** for offline audio storage
- **Status LEDs** for recording, charging, GPS fix indication

## GPIO Pin Assignments

### ESP32-S3 Pin Map
```
GPIO0:  Boot button (pulled high, button to GND for programming)
GPIO1:  Microphone ADC input (ADC1_CH0, 12-bit)
GPIO5:  Record button input
GPIO6:  Status LED 1 (Red - Recording)
GPIO7:  Status LED 2 (Green - WiFi connected)
GPIO8:  Status LED 3 (Blue - GPS fix)
GPIO9:  Charge status input (from BQ24075 CHG pin, active low)
GPIO10: Power good sense (from BQ24075 PG pin, active high)
GPIO12: SPI MISO (microSD card)
GPIO13: SPI MOSI (microSD card)
GPIO14: SPI SCK (microSD card)
GPIO15: SPI CS (microSD card)
GPIO16: UART RX (GPS module)
GPIO17: UART TX (GPS module)
GPIO19: USB D- (native USB for programming/serial)
GPIO20: USB D+ (native USB for programming/serial)
GPIO21: I2C SDA (MAX17048 fuel gauge)
GPIO22: I2C SCL (MAX17048 fuel gauge)
EN:     Reset button (pulled high, button to GND)
```

## Power Architecture

### Power Rails
- **VBUS_5V**: 5V from USB-C connector
- **VBAT**: 3.7V Li-ion battery (1000-2000mAh)
- **VSYS**: System rail from BQ24075 power-path (3.7-5V)
- **VDD_3V3**: Main 3.3V rail @ 1A (from TPSM33615 buck converter)
- **VDD_3V3_GNSS**: Low-noise 3.3V for GNSS (from TPS7A8101 LDO)

### Power Management
1. **BQ24075**: Li-ion charger with power-path management
   - Charges battery from USB at 500mA
   - System can run from USB while charging or from battery alone
   - CHG status output indicates charging state
   - PG (power good) indicates USB power present

2. **MAX17048**: I2C fuel gauge for accurate battery percentage
   - I2C address: 0x36
   - Reports battery voltage and state-of-charge
   - Alert output available (not connected)

3. **Slide Switch**: Hard power disconnect on battery line

## Interfaces

### Audio Input
- 3.5mm TRRS jack with analog microphone support
- Microphone bias voltage: 2.5V
- Op-amp gain: 20x (configurable 10x/20x/40x in module)
- Low-pass filter: ~8kHz cutoff for anti-aliasing
- Output to ESP32 GPIO1 (ADC1_CH0)
- Sampling: 16kHz via ESP32 ADC

### GNSS
- u-blox MAX-M10S module
- UART interface at 9600 baud (default)
- External antenna via u.FL connector
- Update rate: 1Hz (configurable)
- Cold start: ~26 seconds
- Protocols: GPS, GLONASS, Galileo, BeiDou

### MicroSD Card
- SPI interface on HSPI (GPIO12-15)
- Card detect on SD_CD pin
- FAT32 formatted for audio file storage
- Optional backup when WiFi unavailable

### USB-C
- USB 2.0 data (programming & serial debug)
- 5V charging input
- 5.1kΩ CC resistors (USB sink configuration)

## User Interface

### Buttons
- **Record Button** (GPIO5): Start/stop audio streaming
  - Short press: Toggle recording
  - Long press: Power off (firmware controlled)
- **Boot Button** (GPIO0): Enter programming mode (hold during reset)
- **Reset Button** (EN): Hardware reset
- **Power Switch**: Hard power disconnect (slide switch)

## PCB Layout Considerations

### 4-Layer Stackup (Recommended)
1. **Top**: Signal layer (components, traces)
2. **Layer 2**: Ground plane (GND)
3. **Layer 3**: Power plane (VDD_3V3)
4. **Bottom**: Signal layer (traces, connectors)

### Design Guidelines
- **ESP32 antenna**: Keep 5mm clearance from copper pour on PCB edge
- **GNSS power island**: Separate VDD_3V3_GNSS with LC filtering
- **Microphone placement**: Away from switching regulators (>10mm)
- **USB ESD protection**: Close to USB-C connector
- **Battery connector**: Near slide switch and charger IC
- **Decoupling**: 100nF + 10uF near all IC power pins
- **Target size**: ~40mm x 50mm for wearable form factor

## Firmware Behavior

### Startup Sequence
1. Power-on self-test (POST)
2. Connect to WiFi (stored credentials or BLE provisioning)
3. Initialize GNSS module
4. Wait for GPS fix (LED3 blinks)
5. Read battery level from fuel gauge
6. Ready state (LED_PWR solid, others off)

### Recording Flow
1. Press record button → LED1 turns red
2. Start ADC sampling at 16kHz
3. Buffer audio in 100ms chunks
4. Encode to Opus or send raw PCM
5. Stream via WebSocket to `/api/run/stream`
6. Include metadata: timestamp, GPS coords, battery %, sequence number
7. Optional: Mirror to microSD card
8. Press record button again → Stop streaming, LED1 off

### Power Management
- Read battery % from MAX17048 every 10 seconds
- Report in telemetry packets
- Low battery warning at 15% (LED1 blinks)
- Auto-save and shutdown at 5%

## Server API (for reference)

### Endpoints
- `POST /api/run/start` → Returns run ID
- `WebSocket /api/run/stream` → Receives audio chunks with metadata
- `POST /api/run/stop` → Finalizes run, triggers transcription
- `GET /feed` → View past runs with transcribed text and map

### Packet Format (JSON)
```json
{
  "run_id": "uuid",
  "seq": 123,
  "timestamp": 1234567890,
  "gps": {"lat": 37.7749, "lon": -122.4194},
  "battery": 87,
  "audio": "base64_encoded_data"
}
```

## Assembly Notes
1. Solder ESP32-S3 module first (hot air or reflow)
2. Place power components (charger, buck, LDO)
3. Add decoupling capacitors near all ICs
4. Install connectors (USB-C, battery, audio jack, antenna)
5. Program via USB-C with boot button held during reset
6. Test power rails before connecting battery
7. Calibrate microphone gain if needed
